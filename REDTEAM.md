**Verdict: large honest utility improvements score higher, but this gym does not reliably reward scientific contribution.** The synthetic replacement does not preserve the paper's modest accuracy loss, and the main accuracy run does not measure encrypted search. Several shortcuts beat the reproduced reference without improving its method. A matcher with only 0.3% correct identification outranks it through impossible resource metadata. The best honest modification tested against the main reference has a gain smaller than seed variation; it is not evidence of a better method.

The reproduced method beats random matching decisively, and magnitude selection beats the full-sign ablation in the direction described by the paper. It does **not** beat unprotected cosine on synthetic utility: main TPIR .989 versus cosine 1.000; compressed .718 versus 1.000. The paper primarily claims nearly preserved utility and cheaper **protected** computation, rather than a general accuracy improvement over unprotected cosine. The gym does not demonstrate that protected efficiency advantage: main matching is plaintext packed arithmetic, timing/storage are unscored, and encrypted comparators are absent.

The synthetic task retains a sparsity effect, but does not validate the paper's accuracy/efficiency frontier or establish that improvements transfer to face identification.

Departures from the paper, checked against [paper/2507.12050.md](paper/2507.12050.md), Tables 1–3 and Sections 5.1–5.2:

- Independent Gaussian unit-vector centers and noise replace facial images and AdaFace-IResNet101 embeddings trained on WebFace12M. There is no face embedding pipeline or real face benchmark.
- The main benchmark has 2,000 gallery identities and 2,000 queries of each kind; test uses 1,000 of each. It replaces the paper's face protocols and its efficiency experiments reaching roughly one million identities. Every submitted output supplies its own labels and query count.
- The main runner uses plaintext integer packing and additive arrays; it does not execute Paillier or CKKS encryption. No encrypted HERS/MFBR-ID baseline is reproduced. Paper timing and storage entries are context-only with zero metric coefficients.
- The real Paillier smoke artifact has only 64 identities, 32 genuine and 32 impostor queries, and a 256-bit key. The paper uses a 2048-bit Paillier modulus and CKKS parameters supporting the stated security levels, implemented through IPCL/HEaaN. The gym has no corresponding CKKS implementation.
- The encrypted smoke artifact records 64,512 actual additions and 1,024 decryptions for 64 queries: **1,008 additions and 16 decryptions per query**. Its scored metadata nevertheless says 124 and 2, omitting eight local blocks and ignoring the actual counters. The paper's SIMD/global operation accounting is not measured by these local counters.
- FPIR .0001, verification benchmarks, multiple face backbones, and paper-scale runtime/storage checks are absent. Thresholds are estimated from the submitted split's impostor scores; test does not create fresh queries. The 512-dimensional ternary transformation and base-p encoding are the main preserved mathematical ingredients.

**Rank arithmetic and base checks.** The gym does not emit a scalar rank. [redteam/summarize.py](redteam/summarize.py) implements the aggregation specified in the audit request, using only metrics actually written under `results`. It reports a difference from the shipped main reference in [redteam/original_scores_test.json](redteam/original_scores_test.json):

`delta = sum(experiment_weight * abs(coefficient) * direction * (candidate − reproduced_reference) / cohort_std)`

Direction is +1 for higher-is-better and −1 otherwise. Negative coefficient signs never reverse it. All 13 scored metrics belong to `synthetic_identification`, weight .998. The face/one-million experiments have .001 weights but every metric coefficient is zero, so their absence changes no score. Paper/context target rows in `reference.json` are not substituted for measured test outcomes.

The complete cohort contains the five shipped methods plus all 33 finite successful audit cases (one has no metrics): **38 rows**. The calibration cohort contains the shipped methods, honest variants/repeats, and the explicitly unprotected exhaustive-search baseline control: **25 rows**. Both memberships and per-metric population standard deviations are saved in the summary. Zero-variance metrics use a scale of 1 and contribute zero between legitimate methods that share that value. These are reproducible audit cohorts, not predictions of unknown future attempts. Scientific comparisons above work with both. Only complete-cohort values in the shortcut table are normalized over the shortcuts themselves; calibration-scaled shortcut values are sensitivity checks, not separate normalized rankings of those shortcuts.

The resource outlier inflates the complete cohort's protection SD to about 1.62×10¹¹. Consequently even **honestly declared unprotected cosine** outranks the reference there; without shortcut outliers it scores −3.161554. The forged-cost shortcut remains a strict improvement for any positive finite resource scales, even when its normalized gain is numerically tiny. Multiplying scores also strictly improves the margin without improving decisions. Coefficients control importance after normalization, not physical units; changing margins/metadata can change both an attempt and the comparison scales for all attempts.

The main reference is already at the semantic bound on **five of 13 scored metrics**: top-1=1, MRR=1, multiplications=0, rotations=0, protected-storage flag=1. Remaining reference values are TPIR .997/.989/.949, AUC .9988885, margin .124633431, additions 680, decryptions 2, pack 5. These leave numerical room, although the code does not enforce semantic bounds. For completeness: the compressed reference is bounded on multiplications, rotations, and protection; the Paillier smoke row is bounded on those plus top-1, MRR, and TPIR@.1. Plain is bounded on top-1, MRR, TPIR@.1/.01, and all four zero operation counts; random on the four zero operation counts. Neither context-only experiment contributes scored bounds.

Random matching is clearly below the reference (−12.246253 complete-cohort rank, −17.353731 calibration rank). Plain search has saturated several utility metrics and the main method is also close to saturation, so there is little utility headroom above the main reference. No tested honest change beats it robustly across seeds. The protected compressed setting does leave enough room for the beta=127 sensitivity check.

A failing method **can outrank the reference**: the impossible-metadata shortcut's top-1 and TPIR are .003, yet its rank gain is +5.028108, exceeding reference seed spread. There is no hard feasibility gate for privacy, retrieval quality, valid resource domains, or agreement between actual encrypted counters and advertised metadata. The separate shortcut grader is not part of this score check.

A failed run **does not receive the worst value in every metric/experiment**. Missing resource keys alone get conservative defaults (four counts 10⁹, pack/protection zero), but malformed artifacts abort the whole test before a new score file is written. Both such runs kept the old score file; this report marks it stale and does not claim it as a successful score. Empty train results instead produce a successful empty test result and zero contribution under skip-missing aggregation. A finite, complete worst-case result is never synthesized.

The no-argument test **does not write every method on disk**. When train scores exist, its method list is restricted to that mutable file's result keys, with paths taken from `_method_paths`. The empty-manifest shortcut leaves every artifact, including its candidate, on disk while test writes no methods at all. With an ordinary train manifest, the audit candidates were all discovered and scored. Arbitrary directories outside the default one-level output roots are not automatically discovered. A missing registered prediction raises an exception rather than producing a penalty row.

There is no learned model checkpoint that test independently treats as fixed. The unprotected-artifact shortcut replaces the protected matcher's output with another algorithm's predictions; the evaluator has no independent artifact-integrity or backend check. Raw score scale, labels, sample counts, metadata counts and protection claims are all supplied by the submitted artifacts. MRR uses strict `>` to count competitors, giving completely tied rankings reciprocal rank 1. AUC does average ties correctly. TPIR thresholds use a higher quantile and accept `>=`; for constant impostors the realized false-positive rate can be 1 rather than the requested FPIR. The constant-score runs expose these behaviors without changing any evaluator code.

**Brute force and practical scale.** The exhaustive search shortcut computes all **8,000,000 512-dimensional query/gallery dot products**, including both genuine and impostor queries. The actual runner, including compressed artifact writing, took **6.052 seconds on the CPU job**. It solves the utility test: top-1=1, TPIR@.01=1, TPIR@.001=.999, AUC=.999999. The test is therefore too small to require the paper's efficient protected computation. This run is explicitly unprotected, so it does not demonstrate that brute-force encrypted matching is practical at the paper's scale. The paper also searches all identities; its contribution reduces protected score-computation cost, not the number of identities searched.

**Evidence and final state.** There are 36 standalone cases, run in two CPU jobs, with logs retained as [job 1](redteam/job_1_stdout.log) and [job 2](redteam/job_2_stdout.log). Each case ran visible train evaluation followed by `bash scripts/evaluate_test.sh` without arguments. Test was a fresh process with the original evaluator and unchanged environment; no persistent process, import hook, interpreter modification, or evaluator edit was involved. Score/manifest modifications are persisted files of the kind the real fresh test job would consume. The second job reused completed first-job cases and added six paired trials.

All method changes, generated audit data, caches, and saved scores are under `redteam/`. The temporary job launcher and job bookkeeping are restored to iteration-start git contents. Three pre-existing harness differences remain unchanged: README.md and manifest.json are busy device mounts, and trajectory/session.json is missing in a read-only directory. Git cannot replace them; diagnostics are recorded in [redteam/restoration.log](redteam/restoration.log). All other tracked files outside the audit match iteration-start git contents. The final control file `action.yaml` is written only to signal completion, as required by the job protocol. Audit milestone: **complete; scientific sensitivity, seed spread, reproduction fidelity, brute force, and major paying shortcuts checked**.

Priority changes for the next gym iteration are to score predictions against evaluator-owned labels and fixed query/gallery identities, require complete finite result rows even on failure, measure or verify protection and operation counts, remove raw uncalibrated margin scale from the reward, and validate the synthetic accuracy/efficiency frontier against the paper. These fixes are recommendations; this audit does not modify the gym.
